# API слоя `/.well-known`: публичные ключи подписи

> Статус документа: **черновик**. HTTP-контракт слоя `/.well-known` сервиса `backend-auth`.
> Предметная область — `docs/DOMAIN.md`, контракт аутентификации — `docs/API_AUTH.md`, пробы
> состояния — `docs/API_HEALTH.md`, правила работы с кодом — `AGENTS.md`.
> Ключевые слова (ДОЛЖЕН / СЛЕДУЕТ / МОЖЕТ) и маркеры статуса — `docs/DOMAIN.md` §1.3, §1.4.

## 1. Назначение и состав слоя

### 1.1. Маршрут слоя

Слой `/.well-known` отдаёт метаданные сервиса, которые потребители токенов читают без аутентификации.
Сейчас в нём один маршрут — набор публичных ключей подписи (JWKS, RFC 7517). По нему `backend-api`,
`backend-media` и другие сервисы проверяют подпись access-токена офлайн, без обращения к auth за каждым
запросом (`docs/DOMAIN.md` §2).

| Маршрут                      | Назначение                      | Состояние                              |
| ---------------------------- | ------------------------------- | -------------------------------------- |
| `GET /.well-known/jwks.json` | Публичные ключи подписи токенов | `✅` набор публичных JWK из кеша Redis |

### 1.2. Кто публикует ключи

Ключи публикует не эндпоинт, а генерация: при старте и при ротации ключ складывается в Redis
(`docs/DOMAIN.md` §4.3). Маршрут не читает `keyfile` и ничего не публикует — он лишь собирает текущий
набор из кеша. Поэтому набор ДОЛЖЕН быть доступен для чтения без аутентификации: его читают
сервисы-потребители.

## 2. Соглашения

| Параметр         | Значение                                                                            |
| ---------------- | ----------------------------------------------------------------------------------- |
| Базовый префикс  | `/.well-known`                                                                      |
| Метод            | Только `GET`; на тот же путь `HEAD` и `POST` получают 405 с заголовком `allow: GET` |
| Аутентификация   | Не требуется: ключи публичны, их читают сервисы-потребители                         |
| Тело запроса     | Отсутствует                                                                         |
| Тело ответа      | JSON `JSONWebKeySet`                                                                |
| Заголовки ответа | `content-type: application/json`                                                    |
| Формат ошибки    | `{"detail": ...}` — только у 405 от FastAPI; отказ кеша даёт 500 без схемы          |
| Побочные эффекты | Нет: обработчик только читает публичные ключи из Redis                              |
| Тег OpenAPI      | `Служебные метаданные`                                                              |
| Описания         | Swagger UI (`/docs`) и ReDoc (`/redoc`); тексты — `src/api/well_known/docs.py`      |

## 3. Маршрут

### 3.1. `GET /.well-known/jwks.json` — набор публичных ключей

Отдаёт набор публичных ключей подписи, по которым потребители проверяют подпись выданных токенов. Ключи
читаются из Redis (отдельная БД `StorageNumber.KEYS`) — `keyfile` на каждый запрос не читается. Пока ни
один ключ не сгенерирован, ответ приходит с пустым списком `keys`: это корректный ответ, а не ошибка.

- Аутентификация: не требуется.
- Тело запроса: нет. Тело ответа: `JSONWebKeySet`.
- Побочные эффекты: нет.
- Описание в OpenAPI: `JWKS_DOCS` — `summary`, `description`, `status_code = 200`, `deprecated = False`.

| Код | Когда                                    | Тело                               |
| --- | ---------------------------------------- | ---------------------------------- |
| 200 | Набор ключей получен, в том числе пустой | `JSONWebKeySet`                    |
| 405 | Метод не `GET`                           | `{"detail": "Method Not Allowed"}` |
| 500 | Недоступен Redis с публичными ключами    | —                                  |

```bash
curl -i http://localhost:8000/.well-known/jwks.json
```

Ответ (кроме служебных `date` и `server`, которые добавляет uvicorn):

```json
{
  "keys": [
    {
      "use": "sig",
      "kid": "NzbLsXh8uDCcd-6MNwXF4W_7noWXFZAfHkxZsRGC9Xs",
      "kty": "OKP",
      "alg": "EdDSA",
      "crv": "Ed25519",
      "x": "11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo"
    }
  ]
}
```

## 4. Схемы данных

Схемы объявлены в `src/api/well_known/schemas.py` и видны в OpenAPI.

### 4.1. `JSONWebKeySet` — тело ответа

| Поле   | Тип               | Смысл                                                              |
| ------ | ----------------- | ------------------------------------------------------------------ |
| `keys` | `list[PublicKey]` | Набор публичных ключей; пустой список, пока ни один не опубликован |

### 4.2. Публичный ключ

Ключ типизирован по полю `kty` (дискриминатор): `OKP` → `EdDSAKey`, `RSA` → `RSAKey`, `EC` → `ECDSAKey`.
Сервис выпускает только ключи `EdDSAKey` на кривой Ed25519; остальные типы объявлены схемой на будущее.
Приватная часть (`d`) в ответ попадать НЕ ДОЛЖНА.

| Поле  | Тип     | Смысл                                       |
| ----- | ------- | ------------------------------------------- |
| `kty` | OKP     | Тип ключа; дискриминатор набора             |
| `crv` | Ed25519 | Кривая Ed25519                              |
| `x`   | string  | Публичная часть, base64url без паддинга     |
| `alg` | EdDSA   | Алгоритм подписи                            |
| `use` | sig     | Назначение ключа                            |
| `kid` | string  | Идентификатор — thumbprint ключа (RFC 7638) |

## 5. Как контракт описан в коде

| Файл                                      | Что содержит                                                                  |
| ----------------------------------------- | ----------------------------------------------------------------------------- |
| `src/api/well_known/routes.py`            | Маршрут `APIRouter(prefix="/.well-known")` и обработчик `get_jwks`            |
| `src/api/well_known/deps.py`              | Зависимость `get_jwk_publishing_service` — сервис публикации на время запроса |
| `src/api/well_known/schemas.py`           | Схемы `PublicJSONWebKey`, `EdDSAKey`, `RSAKey`, `ECDSAKey`, `JSONWebKeySet`   |
| `src/api/well_known/docs.py`              | Описания для OpenAPI (`JWKS_DOCS`)                                            |
| `src/services/jwk.py`                     | `JWKPublishingService` — собирает публичные JWK из кеша                       |
| `src/providers/cache/repositories/jwk.py` | `PublicJWKRepository` — доступ к ключам в Redis                               |
| `src/providers/cache/_enums.py`           | `StorageNumber.KEYS` — номер БД публичных ключей                              |
| `src/api/__init__.py`                     | Подключение роутера слоя к `main_router`                                      |

Обработчик получает готовый сервис через зависимость (`Depends`), а зависимости сервиса — репозиторий и
клиент Redis на время запроса — собираются в `deps.py`. Схемы ответа валидируются в теле обработчика:
набор из кеша — недоверенные данные, и он приводится к `JSONWebKeySet` с проверкой полей.

## 8. Открытые вопросы

Требуют решения владельца проекта.

1. **Кэширование ответа.** `ETag` и `Cache-Control` сейчас не отдаются; набор меняется только при
   ротации.
1. **Ответ при недоступном Redis.** Сейчас это 500 без схемы ошибки; нужен ли явный код и тело
   (`docs/API_HEALTH.md` §4, `docs/DOMAIN.md` §4.4).
1. **CORS.** Не настроен: браузерный frontend с другого origin к маршруту пока не обратится.

> Файл живой: контракт меняется вместе с кодом — правь `src/api/well_known/` и этот файл в одном
> изменении.
