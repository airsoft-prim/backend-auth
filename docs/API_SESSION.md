# API слоя `/sessions`: маршруты и схемы

> Статус документа: **черновик**. HTTP-контракт слоя `/sessions` сервиса `backend-auth`.
> Предметная область — `docs/DOMAIN.md`; правила работы с кодом — `AGENTS.md`.
> Ключевые слова (ДОЛЖЕН/СЛЕДУЕТ/МОЖЕТ) и маркеры статуса описаны в `docs/DOMAIN.md` §1.3, §1.4.

## 1. Назначение и состав слоя

Слой `/sessions` даёт владельцу управление его активными сессиями: список, закрытие одной сессии и
закрытие всех сессий, кроме текущей. Refresh-токен связан идентификатором `sid` с записью сессии в
Redis (`docs/DOMAIN.md` §4.2). Число активных сессий пользователя не ограничено; новый вход не
закрывает существующие сессии.

### 1.1. Маршруты слоя

| Маршрут                  | Назначение                          | Состояние                            |
| ------------------------ | ----------------------------------- | ------------------------------------ |
| `GET /sessions`          | Список активных сессий владельца    | `✅` работает: сессии из Redis       |
| `DELETE /sessions/{sid}` | Закрытие выбранной сессии           | `✅` работает: отзыв `sid` в Redis   |
| `DELETE /sessions`       | Закрытие всех сессий, кроме текущей | `✅` работает: отзыв остальных `sid` |

## 2. Соглашения

| Параметр        | Значение                                                                             |
| --------------- | ------------------------------------------------------------------------------------ |
| Базовый префикс | `/sessions`; в dev-окружении сервис слушает `http://localhost:8000`                  |
| Аутентификация  | Refresh-токен в HTTP-only cookie `refresh_token` (текущая сессия), а не Bearer-токен |
| Формат обмена   | JSON: `Content-Type: application/json; charset=utf-8`                                |
| Формат ошибки   | Объект `message`, `details`; у отказа валидации (422) — `detail` со списком FastAPI  |
| Время           | UTC, формат RFC 3339                                                                 |

Все маршруты слоя ДОЛЖНЫ принимать refresh-токен из cookie: управление сессиями зависит от текущей
сессии, а не от access-токена. Отсутствие cookie даёт 401, недействительный, просроченный или
отозванный refresh-токен — 403. Сессия должна существовать, принадлежать владельцу
токена, не быть отозванной и не истечь.

## 3. Схемы данных

Схемы объявлены в `src/interface/session/schemas.py`.

### 3.1. `SessionData` — активная сессия

| Поле         | Тип      | Смысл                                                          |
| ------------ | -------- | -------------------------------------------------------------- |
| `id`         | string   | Идентификатор сессии (`sid`)                                   |
| `current`    | bool     | Признак сессии, из которой выполнен запрос                     |
| `created_at` | datetime | Момент входа (UTC)                                             |
| `expires_at` | datetime | Момент истечения сессии (UTC)                                  |
| `ip`         | string   | IP-адрес входа; `null`, если неизвестен                        |
| `platform`   | string   | Платформа входа (ОС) из User-Agent; `null`, если не определена |
| `browser`    | string   | Браузер входа из User-Agent; `null`, если не определён         |
| `location`   | string   | Геолокация по IP; зарезервировано, пока не заполняется         |

### 3.2. `SessionsList` — список активных сессий

| Поле       | Тип             | Смысл                             |
| ---------- | --------------- | --------------------------------- |
| `sessions` | `SessionData[]` | Активные сессии от новых к старым |

## 4. Маршруты

### 4.1. `GET /sessions` — список активных сессий

- Аутентификация: refresh-токен из cookie.
- Ответ 200: `SessionsList`.
- Сессии возвращаются от новых к старым; у текущей сессии (`sid` из refresh-токена) `current = true`.

| Код | Когда                                    | Тело           |
| --- | ---------------------------------------- | -------------- |
| 200 | Список получен                           | `SessionsList` |
| 401 | Cookie отсутствует                       | Тело ошибки    |
| 403 | Refresh-токен недействителен или отозван | Тело ошибки    |
| 500 | Отказ Redis                              | Тело ошибки    |

```bash
curl http://localhost:8000/sessions \
  -H "Cookie: refresh_token=<refresh_token>"
```

### 4.2. `DELETE /sessions/{sid}` — закрытие выбранной сессии

- Аутентификация: refresh-токен из cookie.
- Ответ 204: тело отсутствует.
- Отзывает сессию `sid` владельца: её refresh-токен перестаёт предоставлять доступ к auth.
  Сервисы, проверяющие access-токен автономно через JWKS, не узнают об отзыве и принимают
  ранее выданный access-токен до истечения его срока. Сессия другого владельца или несуществующая даёт 404.

| Код | Когда                                          | Тело        |
| --- | ---------------------------------------------- | ----------- |
| 204 | Сессия закрыта                                 | —           |
| 401 | Cookie отсутствует                             | Тело ошибки |
| 403 | Refresh-токен недействителен или отозван       | Тело ошибки |
| 404 | Сессия не найдена или не принадлежит владельцу | Тело ошибки |
| 500 | Отказ Redis                                    | Тело ошибки |

```bash
curl -X DELETE http://localhost:8000/sessions/<sid> \
  -H "Cookie: refresh_token=<refresh_token>"
```

### 4.3. `DELETE /sessions` — закрытие всех сессий, кроме текущей

- Аутентификация: refresh-токен из cookie.
- Ответ 204: тело отсутствует.
- Закрывает все активные сессии владельца, кроме сессии, из которой выполнен запрос.

| Код | Когда                                    | Тело        |
| --- | ---------------------------------------- | ----------- |
| 204 | Остальные сессии закрыты                 | —           |
| 401 | Cookie отсутствует                       | Тело ошибки |
| 403 | Refresh-токен недействителен или отозван | Тело ошибки |
| 500 | Отказ Redis                              | Тело ошибки |

```bash
curl -X DELETE http://localhost:8000/sessions \
  -H "Cookie: refresh_token=<refresh_token>"
```

## 5. Как контракт описан в коде

| Файл                               | Что содержит                                        |
| ---------------------------------- | --------------------------------------------------- |
| `src/interface/session/routes.py`  | Маршруты `APIRouter(prefix="/sessions")`            |
| `src/interface/session/deps.py`    | `CurrentSession` из refresh-токена; сборка use case |
| `src/interface/session/schemas.py` | `SessionData`, `SessionsList`                       |
| `src/interface/session/docs.py`    | Описания для OpenAPI (`RouteDocs`)                  |
| `src/application/session.py`       | `CreateSession`, `ListSessions`, `CloseSession`     |

`get_current_session` берёт владельца и `sid` из проверенного refresh-токена (cookie), а не из
access-токена: управление сессиями привязано к текущей сессии.

## 6. Сводка кодов ответов

| Код | Когда                                    | Маршруты                                     |
| --- | ---------------------------------------- | -------------------------------------------- |
| 200 | Список получен                           | `GET /sessions`                              |
| 204 | Сессия(и) закрыта(ы)                     | `DELETE /sessions/{sid}`, `DELETE /sessions` |
| 401 | Cookie отсутствует                       | все                                          |
| 403 | Refresh-токен недействителен или отозван | все                                          |
| 404 | Сессия не найдена или чужая              | `DELETE /sessions/{sid}`                     |
| 500 | Отказ Redis                              | все                                          |

> Файл живой: контракт меняется вместе с кодом — правь `src/interface/session/docs.py` и этот файл в
> одном изменении.
